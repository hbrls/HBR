# 微信个人小程序：客服、通知与上架能力调查

> updated_by: HBR（Codex） - GPT-6
> updated_at: 2026-11-23 23:19:23
> 调查日期：2026-11-23（北京时间）
> 调查口径：腾讯微信平台的公开能力、主体权限及规则；未使用实际个人小程序账号做送达测试。

## 一、核心结论

**个人主体的小程序支持程序化接收和回复客服消息，并可在自己的客服会话里发送原生小程序卡片。使用这组官方接口不要求人工客服登录工作台，也不要求配对公众号。** 个人小程序同时支持订阅消息，但客服会话和订阅消息有不同的触发条件、展示位置与发送限制。[1][2][3][4]

| 核心问题 | 调查结论 |
| --- | --- |
| 个人小程序有没有程序化客服能力？ | **有。** 微信可以推送用户消息，程序可以调用官方客服接口回复。[1][2][3][4] |
| 是否必须有人接待？ | **程序化回复不以人工登录或逐条操作为前提。** 官方消息推送文档提供自动回复示例。[4] |
| 能否在客服聊天里发小程序卡片？ | **可以。** 支持标题、封面和小程序页面路径；受客服发送窗口和额度限制。[2][3] |
| 发客服卡片是否要用户订阅？ | **不需要。** 需要用户先触发相应客服互动。[2] |
| 用户连续发消息，能否持续回复？ | **可以持续刷新额度和时限。** 每次用户发消息后可发额度恢复到 5 条，48 小时重新起算，额度不累加。[2] |
| 能否在没有互动和订阅时随时主动发？ | **不能。** 客服消息需要互动窗口；普通订阅消息需要对应的成功订阅。[2][7] |
| 能否自动发到任意微信好友或群聊？ | **公开的小程序客服接口不提供这项能力。** 普通聊天分享由用户发起，客服接口作用于对应客服会话。[2][3][12] |
| 个人小程序上架是否强制付费微信认证？ | **公开规则未把付费微信认证列为个人主体上架的统一前置条件。** 腾讯将个人账号的搜索、分享能力列为认证后权益；明确要求认证后上架的是非个人主体。[5] |
| 同一人能注册几个个人小程序？ | **同一身份证最多 5 个。** 小程序注册额度与公众号额度分开。[6] |

## 二、个人主体的权限依据

本报告中的“个人小程序”指注册主体为个人，不包括企业或个体工商户。

腾讯客服《个人类型具备什么功能》明确把“订阅消息”“客服消息”列为个人小程序支持能力。微信《发送客服消息》第 7 节的权限表将“小程序”标为可用；同一表将公众号、服务号标为“仅认证”。两项材料结合，可确认个人主体有普通客服消息能力，不能把公众号的认证门槛套到个人小程序上。[1][3]

该发送接口第 5.11 节列出原生小程序卡片，第 2 节列出卡片标题、封面和页面路径。普通小程序客服指南明确支持的消息类型是**文字、图片、小程序卡片**。[2][3]

**文档混用的注意点：** 发送接口页面还出现公众号菜单、公众号图文、语音、视频等通用内容。不能据此把页面中所有消息类型都视为个人小程序已确认支持。本报告以个人能力说明、普通小程序客服指南和账号权限表交叉核对。[1][2][3]

## 三、“小程序客服”是什么，能否完全程序化使用

### 用户看到的会话

用户从小程序内的客服入口进入微信提供的聊天界面。使用过的客服会话会聚合在微信聊天列表的“小程序客服消息”中；用户离开小程序后，仍可从这里查看历史并继续发消息。它是该小程序的客服会话，不是给一个普通微信好友发私信。[2]

### 程序可以做什么

| 能力 | 平台支持情况 |
| --- | --- |
| 接收新消息与进入会话事件 | 支持微信将消息和事件推送到小程序配置的接收端。[4][13] |
| 自动回复用户 | 支持调用官方发送接口。消息推送文档直接提供收到消息后自动回复“收到”的示例。[3][4] |
| 发送原生小程序卡片 | 支持，点击卡片可进入指定的小程序页面。[3] |
| 管理客服账号及查询在线客服 | 官方小程序客服接口目录列有添加、删除、查询、设置管理员等能力；这是客服人员管理能力。[14] |
| 拉取客服工作台全部历史聊天或待接待列表 | 本次检查的普通小程序客服公开接口目录未列出这类接口；不能把“接收新消息推送”描述成“可拉取工作台全部历史”。[13][14] |

以上是平台能力清单，不构成开发方案。

### 客服小助手、网页工作台与接口的关系

微信提供了三种客服消息发送方式：官方接口、网页客服工具、移动端“客服小助手”。**人工工具是可选方式，不是调用消息接口的必要步骤。** 未启用消息推送时，微信将用户消息转给官方客服工具；启用消息推送后，可以按官方规则接收消息并调用接口回复。[2]

公开指南给出的客服人员绑定上限为 100 人，该数字是普通小程序客服指南的通用规则，不是“个人程序化客服必须绑定 100 人”或必须绑定人工的要求。[2]

发送接口的简介确实写有“主要应用在有人工消息处理环节的场景”，但不能把这句定位说明解释为“禁止程序自动回复”。同一套官方材料提供了自动回复示例；发送接口还提供 AI 回复标记字段，可显示“内容由第三方 AI 生成”。这些材料确认程序化回复能力，但不代表任何服务内容都免于类目及内容规则审核。[3][4]

## 四、客服发送的时限与条数

| 用户动作 | 允许下发数量 | 有效发送时间 |
| --- | --- | --- |
| 用户仅进入客服会话 | 最多 2 条 | 1 分钟 |
| 用户主动发送消息 | 最多 5 条 | 48 小时 |

微信明确规定：条数不累加；新用户动作会更新可发送数量和时限，采用当前可发送数量限制的最大值和最长有效时间。用户再次主动发消息后，可发送额度恢复至 5 条，48 小时从这次消息重新起算。[2]

| 例子 | 结果 |
| --- | --- |
| 用户连发 3 条，客服尚未回复 | 仍可发 5 条，不会累积为 15 条。 |
| 客服已发 4 条，用户又发 1 条 | 可发送额度恢复至 5 条。 |
| 用户发消息后，客服已连续发完 5 条，用户未再发 | 即使尚未超过 48 小时，也不能继续发第 6 条。 |
| 用户发消息后不再互动 | 后续回复和结果卡片共用剩余额度，且须在发送时限内完成。 |
| 用户持续真实互动，客服持续回复 | 这条规则没有“整场对话总共只能 5 条”的限制，但每次下发仍受当前额度和时限约束。 |

上表是对官方刷新规则的直接应用。文字、图片、卡片都是客服下发消息，占用同一额度。制作完成事件不会自行续期，也不会自动增加额度。[2]

因此，之前“几乎无限”的表述应收紧为：**用户持续真实互动时，可以持续对话；不能把它理解为无限主动推送。** 公开的 5 条及 48 小时规则不等于平台对无限总量、速率或永不风控作出承诺。微信明确禁止恶意诱导用户发消息来获得发送权限，也禁止无关骚扰、恶意营销和违法内容。[2]

## 五、两种通知模式的区别

| 比较项 | 一次性订阅消息 | 客服会话中的小程序卡片 |
| --- | --- | --- |
| 个人主体支持 | 支持。[1] | 支持。[1][2][3] |
| 用户在哪里收到 | 微信“服务通知”。[7] | 对应小程序客服会话。[2] |
| 用户前置动作 | 成功订阅对应模板。[7][8] | 进入客服会话或主动发消息。[2] |
| 内容形式 | 微信模板的标题及字段，可跳转结果页。[7][11] | 原生小程序卡片，可设置标题、封面及页面路径。[3] |
| 主要发送限制 | 每次对某一次性模板成功订阅，对应一条消息。[7] | 依用户动作适用 2 条／1 分钟或 5 条／48 小时。[2] |
| 是否有客服的 48 小时时限 | 官方说明一次性订阅成功后，可不限时间下发对应的一条消息。[7] | 有。[2] |
| 能否不取得前置权限就自动发 | 不能。[7][8] | 不能。[2] |

图文正文可以放在小程序结果页，通知或卡片提供入口。“发一条小程序卡片”不等于把完整长图文正文作为聊天消息直接推送。[3][11]

### 一次订阅究竟意味着什么

针对同一个一次性模板，成功订阅一次对应一条消息。用户勾选“总是保持以上选择，不再询问”后，下一次请求同一模板可以沿用选择、省去弹窗；**记住同意不会变成长久无限发送权限。** 每条新通知仍需要取得相应订阅次数。订阅申请有微信规定的用户点击或支付等触发条件，不能在后台无条件无限申请。[7][8][9]

订阅模板取决于账号类目和实际服务场景。后台公共模板库没有合适模板时，可申请新增，审核通过后使用。本次未确认某个个人账号当前可选的“制作完成”模板，因此不指定一个未经确认的模板名称或编号。[9][10]

长期订阅仅向微信指定的公共服务等场景开放。新版免弹窗订阅 Beta 也受类目、业态及支付或指定服务动作约束，不能当成个人小程序通用的免授权推送方式。[7][15]

## 六、普通聊天分享及其他客服模式的边界

小程序可以由用户主动转发到微信好友或群聊；这项分享能力与小程序客服消息是两回事。公开客服 API 没有提供向任意好友或群聊自动发送小程序卡片的能力。[3][12]

企业微信“微信客服”另有接收和发送接口，支持在其客服会话中发小程序消息，同时有其自己的接待状态、时限和额度要求。**它属于另一种平台模式，不能作为个人小程序自身权限的依据。**[21]

个人主体不能使用本次核对的 URL Link 生成能力：该官方接口明确仅向国内非个人主体开放。个人主体支持自定义二维码／小程序码，但不同入口是否可用仍应与认证后的分享权益分开核对。[1][5][22][23]

客服子商户也不是所有个人小程序都能用：官方仅向“电商平台”类目开放，而该类目不在个人主体开放类目表内。[2][16]

## 七、注册、认证和上架条件

### 主体与数量

- 同一身份证最多注册 5 个个人小程序。
- 小程序注册数量与公众号注册数量分开计算。
- 个人主体与个体工商户是不同主体类型，不应混用其权限和资质结论。[6]

### 付费微信认证与上架

**按腾讯当前公开说明，个人小程序不以付费微信认证作为统一的发布上架前提。** 其依据是：腾讯将个人账号认证后的权益列为认证标识、被搜索和分享；而对非个人账号另行明确规定“需完成微信认证后方可发布上架”。这里的个人上架结论是对官方主体差异说明的解读，不是“免除所有上线审核”。[5]

认证、身份核验、备案和版本审核应分别看待：

| 事项 | 个人小程序的结论 |
| --- | --- |
| 注册时身份核验 | 仍须满足个人注册及身份核验要求。 |
| 付费微信认证 | 未被列为个人发布上架的统一前提；腾讯将搜索、分享列为认证后的权益。[5] |
| 认证费用 | 腾讯个人认证指引的付款截图示例为 30 元／次；每次申请收取审核服务费，不以认证成功为条件。实际以当次协议和付款页为准，不把该示例写成已核实的永久年费标准。[17] |
| 普通客服消息权限 | 个人功能说明及发送权限表支持该能力，没有对个人另列“仅认证”条件。[1][3] |
| 备案与版本审核 | 面向中国大陆公开上线仍须按适用规则完成备案和审核。[18][19] |

**“能上架”“能调用客服接口”“能被搜索”“能被用户分享”是不同问题。** 个人账号无需付费认证即可拥有普通客服接口权限，不代表未经认证就必然拥有完整传播能力。未认证个人账号发送客服卡片后的实际展示和跳转，本次没有进行真机验证，不能以接口权限表代替这项实测。[3][5]

### 类目、内容和其他前置条件

小程序须按实际向用户提供的服务选择类目。个人主体只可使用微信对个人开放的类目，部分服务仅向非个人主体或具备特定资质的主体开放。[16]

面向中国大陆公众提供服务，须完成适用的小程序备案；涉及前置审批的服务，需要对应审批文件。备案不同于付费微信认证，也不同于版本审核。[18][19]

图文展示本身不改变客服和订阅消息的发送机制，但内容与实际服务会影响类目和资质。若实际提供 AI 创作、AI 绘画等深度合成服务，应核对官方相应类目的主体、资质与生成内容标注要求，不能因为通过客服入口提供服务就视为豁免。发送接口支持 AI 回复标记也不构成相关类目准入许可。[3][16]

客服内容须遵守小程序运营规范及客服使用规范，与用户请求相关，不得通过消息机制发送骚扰或违规内容。[2][20]

## 八、已确认与未确认的边界

**已通过公开官方材料确认：**

- 个人小程序支持客服消息及订阅消息。
- 客服消息具有程序化接收、回复及发送原生小程序卡片的能力。
- 自动回复不要求人工登录官方客服工具。
- 客服窗口的触发条件、5 条／48 小时、2 条／1 分钟及不累加刷新规则。
- 普通一次性订阅的一次一条、记住选择与长期授权的区别。
- 个人主体注册上限、认证权益，以及类目、备案和审核的前置要求。

**没有进行的账号级验证：**

- 正式个人账号的后台权限与所选服务类目。
- 未认证和已认证个人账号的卡片送达、显示及结果页跳转。
- 目标账号能申请的具体订阅模板、编号和字段。
- 真机上的发送成功率、额度刷新结果及客户端通知呈现。

最终判断应表述为：**腾讯公开规则支持“个人小程序＋程序化客服消息＋客服会话内小程序卡片”这一模式；也支持个人小程序的一次性订阅通知。具体账号的发布、传播权益、模板和送达结果仍须满足相应条件。**
